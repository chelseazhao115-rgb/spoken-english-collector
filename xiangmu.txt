# AI Spoken English Collector — V1 产品与开发规格

## 1. 产品定位

### 暂定名称

**Spoken English Collector**

中文暂定：

**生活英语表达采集器**

### 一句话介绍

帮助英语学习者在浏览 YouTube、视频、文章等真实英文内容时，通过文字选取或区域截图快速采集值得学习的生活化表达，并自动完成识别、释义、场景分类、整理与导出。

### 核心用户问题

用户在真实英文内容中经常遇到：

* 不认识的词；
* 很自然但自己不会说的表达；
* 地道搭配；
* 口语句型；
* 很适合以后使用的表达。

但传统积累流程过长：

发现表达
→ 暂停内容
→ 截图 / 复制
→ 打开词典
→ 查中文
→ 查音标
→ 记录原句
→ 写使用场景
→ 保存到 Notion / Excel / Obsidian
→ 后续手动整理。

大量用户因此选择：

> “算了，以后再记。”

本产品希望把这一过程缩短为：

**发现表达 → 框选 → AI 自动整理 → 用户确认 → 保存**

---

# 2. V1 核心价值

产品不定位为：

* OCR 工具；
* 截图工具；
* 普通电子词典；
* 背单词软件。

而定位为：

> **真实英语输入中的个人口语表达采集与整理工具。**

核心价值包括：

### 1）降低采集摩擦

用户不需要在多个软件之间切换。

### 2）识别“值得学的表达”

AI 不只是识别单词，而是判断：

* idiom；
* collocation；
* phrasal verb；
* conversational phrase；
* sentence pattern；
* native-like expression。

### 3）自动结构化

自动补充：

* 中文释义；
* 音标；
* 上下文含义；
* 使用场景；
* 同义 / 相似表达；
* 标签；
* 来源。

### 4）减少后续整理工作

自动按照：

* 日期；
* 使用场景；
* 表达含义；

进行组织。

### 5）让用户拥有自己的数据

支持导出为排版良好的独立 HTML 文件。

---

# 3. 核心用户

V1 核心用户：

有一定英语基础、希望提升真实生活口语表达的英语学习者。

典型特征：

* 会看 YouTube / Vlog / Interview / Podcast Video；
* 已经不满足于单纯背单词；
* 经常发现“这个表达很好，但我不会说”；
* 有积累表达的习惯或意愿；
* 觉得 Notion / Excel 手动整理过于麻烦；
* 更关注地道表达和真实使用场景。

V1 不优先服务：

* 零基础学习者；
* 单纯准备四六级词汇的人；
* 只需要英汉词典的人；
* 专业论文词汇学习；
* 大规模字幕翻译。

→ Save。

# 6. V1 功能范围

V1 只完成以下六个核心能力。

## Feature 1 — Capture

支持：

### A. Select Text

如果网页文字可以复制：

用户选择文字后直接发送到插件。

### B. Region Capture

用户点击：

**Capture Expression**

页面：

* 出现半透明遮罩；
* 鼠标拖动选择区域；
* 生成选区截图；
* 自动发送 OCR。

必须支持：

* ESC 取消；
* 重新截图；
* DPI / 页面缩放适配；
* 截图时隐藏选择框 UI。

---

# 7. Feature 2 — OCR

输入：

区域截图。

输出：

识别后的英文文本。

V1 优先：

**Tesseract.js，本地 OCR。**

OCR 之后必须经过用户确认，不允许直接提交 AI。

界面：

```text
Detected Text

I wouldn't read too much into it.

[Edit]

[Analyze]
```

如果 OCR 错误：

用户可以直接修改文本。

V1 不追求极端 OCR accuracy。

重点是：

> OCR + User Correction 可以完成任务。

---

# 8. Feature 3 — AI Expression Analysis

AI 的目标不是“把所有单词都解释一遍”。

AI 必须识别：

> **这句话里最值得英语学习者积累的口语表达是什么。**

优先提取：

* idioms；
* collocations；
* phrasal verbs；
* conversational phrases；
* spoken sentence patterns；
* natural native-like expressions。

普通基础词汇默认不提取。

例如：

```text
I wouldn't read too much into it.
```

应该识别：

```text
read too much into something
```

而不是：

```text
read
much
into
```

---

# 9. AI 输出 Schema

AI 必须使用固定 structured JSON。

禁止前端解析自然语言。

建议 Schema：

```json
{
  "sentence": "I wouldn't read too much into it.",
  "sentence_translation_zh": "我不会对此过度解读。",
  "has_useful_expression": true,
  "expressions": [
    {
      "expression": "read too much into something",
      "ipa": "",
      "meaning_zh": "对某件事情过度解读",
      "meaning_in_context_zh": "这里表示不要赋予某件事情过多意义。",
      "usage_zh": "当别人对一句话、一个行为或某件小事进行了过度分析时使用。",
      "naturalness": "very_natural",
      "expression_type": "idiomatic_phrase",
      "semantic_group": "OVERINTERPRET",
      "scene_tags": [
        "Daily Conversation",
        "Relationships",
        "Opinions"
      ],
      "alternatives": [
        {
          "expression": "Don't overthink it.",
          "meaning_zh": "别想太多。"
        },
        {
          "expression": "Don't make too much of it.",
          "meaning_zh": "别把这件事看得太重。"
        }
      ]
    }
  ]
}
```

允许：

```json
{
  "has_useful_expression": false
}
```

表示 AI 判断：

> 该句没有特别值得积累的口语表达。

此时用户仍然可以：

**Save Anyway**

# 10. Expression Record 数据结构

数据库中的一条记录至少包含：

```ts
interface ExpressionRecord {
  id: string;

  originalSentence: string;
  sentenceTranslationZh: string;

  expression: string;
  ipa?: string;

  meaningZh: string;
  meaningInContextZh: string;
  usageZh: string;

  expressionType:
    | "idiom"
    | "collocation"
    | "phrasal_verb"
    | "sentence_pattern"
    | "conversational_phrase"
    | "word"
    | "other";

  naturalness:
    | "very_natural"
    | "natural"
    | "neutral";

  semanticGroup: string;

  sceneTags: string[];

  alternatives: {
    expression: string;
    meaningZh?: string;
  }[];

  sourceType:
    | "youtube"
    | "web"
    | "image"
    | "other";

  sourceTitle?: string;
  sourceUrl?: string;
  sourceTimestamp?: string;

  capturedAt: string;
  updatedAt: string;

  userEdited: boolean;
}
```

# 11. Semantic Group 与 Scene Tag 必须分离

这是产品的重要设计原则。

## Semantic Group

回答：

> “它在表达什么意思？”

例如：

```text
VERY_BUSY
```

包含：

* I'm swamped.
* I'm slammed.
* I've got a lot on my plate.
* Things are hectic.

---

## Scene Tag

回答：

> “它在什么生活场景可能出现？”

例如：

```text
Work
Study
Relationships
Travel
Shopping
Food
Socializing
Making Decisions
Emotions
Opinions
Daily Conversation
```

例如：

```text
I'm swamped.
```

可以属于：

Semantic Group：

```text
VERY_BUSY
```

Scene：

```text
Work
Study
Daily Conversation
```

两套体系禁止混为一个 Tag 系统。

# 20. Storage

V1 不开发账号和云数据库。

### chrome.storage.local

用于：

* settings；
* API configuration；
* lightweight preferences。

### IndexedDB

用于：

* Expression Records；
* collection；
* tags；
* local data。

V1 默认不长期保存截图。

流程：

```text
Screenshot
↓
OCR
↓
Text generated
↓
Screenshot discarded
```

* 存储膨胀；
* 隐私问题；
* 数据复杂度增加。

# 25. Vibe Coding 开发原则

Codex 必须遵循以下原则：

### 1. 一次只完成一个 Milestone

禁止同时开发多个大功能。

### 2. 每个 Milestone 必须先跑通核心流程

再做样式。

### 3. 不允许主动增加 Scope

发现可能有价值的新功能：

记录到：

```text
FUTURE_IDEAS.md
```

不直接开发。

### 4. 数据 Schema 一旦确定不得随意改字段名称

如果确实需要修改：

必须同步更新：

* types；
* database；
* AI schema；
* UI；
* export。

### 5. AI 输出只允许 Structured JSON

不允许依赖自然语言解析。

### 6. 每完成 Milestone 必须：

* 自测；
* 汇报完成内容；
* 汇报遗留问题；
* 明确当前项目是否满足验收条件。

# 26. Codex Milestone 1

## Goal

实现：

**区域截图 → OCR → Side Panel 显示文字**

暂时不接 AI。

### Required Flow

```text
User clicks Capture
↓
Page enters selection mode
↓
User drags rectangle
↓
Selected region captured
↓
Image cropped correctly
↓
OCR runs
↓
Detected English displayed
↓
User can edit text
```

### Acceptance Criteria

1. 普通网页可以启动截图；
2. 鼠标可以框选区域；
3. ESC 可以取消；
4. 截图区域与用户选择区域一致；
5. Windows 页面缩放 / devicePixelRatio 不导致明显偏移；
6. OCR 能识别清晰英文字幕；
7. OCR 结果允许修改；
8. 页面刷新后插件不会进入异常状态；
9. 不开发数据库；
10. 不开发 AI；
11. 不开发 Export。

完成后停止。

# 31. 给 Codex 的项目总约束

在整个开发周期中，请始终遵守：

> 本项目的目标不是构建一个完整的英语学习平台，而是在尽可能短的开发周期内完成一个稳定、可演示、流程闭环的 AI Spoken English Collector V1。

核心闭环：

```text
Capture
→ OCR
→ AI Analyze
→ User Confirm
→ Save
→ Organize
→ Export
```

任何不直接服务该闭环的功能都不属于当前开发范围。

如果发现新的产品机会：

记录，而不是实现。

优先级始终是：

```text
Core Flow Stability
>
Data Correctness
>
AI Output Reliability
>
Usability
>
Visual Polish
>
Additional Features
```

避免：

* 为未来过度设计；
* 提前抽象；
* 大规模重构；
* 自作主张扩大 Scope；
* 在核心流程尚未稳定时增加功能。

当 V1 的五个 Milestone 全部通过验收后：

项目进入完成状态。
